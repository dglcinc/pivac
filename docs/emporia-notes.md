# Emporia Vue — circuit history, CT scaling and dashboard conventions

Evidence and history behind the Emporia rules in `CLAUDE.md`.

## Emporia paired-CT circuits were half-scale before 2026-07-04 (FIXED)

the house panel's four 240 V circuits (`utility_sub_panel`, `hall_subpanel`, `wall_oven`, `bosch_bova`) are each monitored by **two CTs, one per leg** (channels 1+2, 3+4, 5+6, 7+8, same circuit name, multiplier 1.0 — the *correct* Emporia hardware setup). `pivac.Emporia` used to emit each channel separately, so both legs landed on the same SK path and the second overwrote the first — **InfluxDB history for those four measurements before 2026-07-04 ~16:30 EDT is one leg only (≈½ actual for balanced 240 V loads)**. Clamp-verified: BOVA at 9.4–9.5 A/leg ≈ 2.27 kW while Emporia showed ~1.15 kW. The module now sums same-named channels before emitting (energy balance closes: main = Σ circuits + balance). Do **not** "fix" this by setting a ×2 multiplier in the Emporia app on these circuits — that would double each leg and make the summed value 2× high. The ×2 multiplier is only for single-CT 240 V circuits. Any capacity analysis based on pre-fix data (e.g. the "both BOVAs at ⅓ max" zone analysis) must be rescaled ×2.

### A renamed Emporia circuit used to look like a dead sensor (FIXED 2026-08-13, PR #109)

`pivac.Emporia` read channel names once and cached them for the life of the daemon, so renaming a circuit in the app had no effect until someone restarted the service by hand. Because **the channel name becomes the Signal K path**, the module kept publishing the old path while Emporia reported the new one — which presents as a *sensor that has gone stale*, not as a naming problem. `_get_device_cache()` now refreshes on a TTL (**`name_refresh_s`, default 3600 s**) rather than every cycle (`populate_device_properties()` is an extra cloud call per device against a 60 s poll); a refresh that raises **keeps the previous names**; and a detected rename logs at WARNING with the reminder that the old path stays frozen until signalk restarts. Same shape as the OneWireTherm boot-race. **NB the change-detection WARNING only fires on a refresh inside a running process** — on a restart the cache starts empty and it logs "Discovered" at INFO, so its absence after a restart proves nothing.

### Circuit names are sanitized to `[a-z0-9_]` (FIXED 2026-08-13, PR #110)

Emporia labels are free text, and `_sanitize` used to pass everything it did not explicitly strip straight through — producing `don't_know` and `microwave_+_refrigerator`, both of which need quoting in InfluxQL. The latent case was worse: **a `.` survived**, and a circuit labelled "Circ. Pump" would have silently produced `…house.circ..pump`, nesting the SK path an extra level instead of failing visibly. Now a whitelist: separators (`\s / - + & ,`) → `_`, anything else dropped, underscore runs collapsed, empty → `unnamed`. `tests/test_emporia_sanitize.py` (dependency-free, run `python tests/test_emporia_sanitize.py`) asserts **every in-service name sanitizes to itself**, because a change there would orphan that measurement's history.

### ⚠️ Single-CT-doubled only works for a BALANCED 240 V load — it hides standby draw (diagnosed 2026-08-13)

The Chiltrix read ~0 W at idle on a single CT with a ×2 multiplier. InfluxDB over 24 h showed **0 samples ≤0.5 W, min 1 W, max 3599 W** — the CT never truly read zero, it bottomed out. The compressor is a balanced 240 V load and read correctly; the **pump, controls transformer and crankcase heater are 120 V loads on one leg**, and the CT was watching the other one. Moving to a **merged pair** (two CTs, one per leg, same circuit name) surfaced ~10 W idle — the split was measured mid-move as 0.9 W + 9.3 W, which confirmed it. **Rule of thumb: use ×2 single-CT only where you are sure the load is balanced; any equipment with an internal pump or controls wants a merged pair.** **And reset the multiplier to 1.0 when merging** — leaving ×2 on a pair makes it 2× high (the inverse of the 2026-07-04 half-scale bug). Merging keeps the circuit name, so no history is orphaned.

### Grafana House Power (panel 10) conventions

stacked area with **`main` excluded from the stack** via a per-series `custom.stacking: none` override — left in, it would be piled on top of the circuits that already sum to it. **`balance` must be plotted** (as "Everything else") or the stack cannot reach `main`; on this panel it is often the largest band. The **great-room BOVA is metered on the utility subpanel**, so plotting both double-counts it — netted out with `joinByField` → `calculateField` (gross − great-room BOVA) → `organize`, the same technique that nets irrigation out of domestic water, since InfluxQL cannot subtract across measurements. Queries carry **aliases** so the transform references readable field names. **⚠️ Emporia's `balance` is NOT nesting-aware — a nested CT needs TWO corrections, not one (measured 2026-08-13).** Emporia computes `balance = main − Σ(every circuit)`, counting a nested circuit as if it were independent, so `balance` is **depressed by exactly the nested draw**. Netting the great-room BOVA out of the utility subpanel *without* adding it back to balance removes it twice. Caught live with the BOVA running: `bova_great_room` 599.0, `utility_sub_panel` 847.4, `balance` 16.3, `main` 2043.8 — the stack reached **1444.9, short by 598.9**. The panel therefore does **both**: `utility_sub_panel − bova_great_room` → "Utility subpanel", **and** `balance + bova_great_room` → "Everything else" (Emporia's raw balance is kept as an intermediate field and excluded from display). Verified: 2043.9 vs main 2043.8. **Any future nested CT needs the same pair of corrections** — and the unstacked `main` overlay is what makes the shortfall visible, so keep it. **Colour scheme is by load family, not by palette order (2026-08-14):** every displayed series carries an explicit `byName` fixed-colour override — **blue = cooling equipment** (Chiltrix `#1F5FBF`, kitchen BOVA `#4C9BE8`, great-room BOVA `#A8D3F5`), **yellow = subpanels** (utility `#C99700`, hall `#F7E77A`), **green = individual loads** (wall oven `#1B6B36`, microwave+fridge `#3D9A57`, downstairs bath floor `#7ECB8B`, unidentified ch 8 `#C6E9C1`), plus neutral `text` grey for the "Everything else" catch-all and `purple` for the unstacked `main` overlay (it must **not** be blue — it would read as a fourth cooling series). The `organize` transform's `indexByName` orders the stack in those same family blocks so the legend groups visually. Hex rather than Grafana's named shades because adjacent named steps (e.g. `blue`/`semi-dark-blue`) are too close to tell apart in a 10-series stack. **A new circuit needs a colour override added** — without one it falls back to `palette-classic` and lands on an arbitrary hue that breaks the grouping. **Apartment Power (panel 11) follows the same scheme** so the two panels read alike: `main` `purple`, `balance` `text` grey, air conditioner `#1F5FBF` (same blue as the house's primary cooling unit), furnace `#3D9A57`. The furnace is deliberately **green, not blue** — blue means *cooling* here, and the whole point of that panel is comparing AC against furnace, which is easier when they are in different families. There are no subpanels in the apartment, so nothing is yellow. NB panel 11 matches overrides on the **raw field name** (`electrical.emporia.apartment.<circuit>.mean`) with a separate `displayName` property, whereas panel 10 aliases in the query and matches the alias — so a circuit rename breaks panel 11's overrides silently (the series reverts to `palette-classic`), while panel 10 loses the series outright. When the borrowed apartment CTs come back, the returning circuits are green.
