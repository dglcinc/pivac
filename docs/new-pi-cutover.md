# New Pi cutover — procedure

**Status:** ready to run. The new Pi (`new-pivac`, Pi 4 Model B Rev 1.5, `eth0`
`2c:cf:67:80:55:00`) has both boards proven on the bench: all eleven I/O channels
(`scripts/io-board-test.py`, 2026-09-06) and the DS2482 1-wire board with a probe on H1
(2026-09-07). This document is the order of operations for taking the old Pi out of the panel,
putting the new one in on the weekly clone card, moving the field wiring onto the plugs, and
proving it before walking away. · **Owner:** David

Design and build detail live elsewhere and are not repeated here:
`docs/rpi-io-board-design.md` (I/O board, §2.1 channel map, §4.3 plugs),
`docs/ds18b20-bus-topology.md` (1-wire board, §7 field bus, §8 software),
`docs/cdp-chiller-rework-plan.md` (relay roster, zone map), and `CLAUDE.md` (services, network,
backup). The label is `docs/PhoenixContact-BC-RPI-label.docx`, regenerated by its `.gen.py`.

Budget about half a day. The house is unmonitored from step 2 until step 8; the freshness alerts
will fire at 30 minutes and clear on their own once Signal K is back.

## 0. Before the panel is opened

Everything in this section is done at a desk, and none of it is reversible-only-by-rewiring.

1. **Merge the open PRs**: #159 (bench-test script), #160 (EXT board solder-side sheet), #161
   (`ds2482-init.service` and the 1-wire doc as built) and the PR that carries this document.
   Then on the old Pi:
   ```bash
   ssh pi@10.0.0.82 'git -C ~/github/pivac pull --ff-only && git -C ~/github/pivac log --oneline -1'
   ```
   The clone in step 1 copies that checkout, so the new Pi boots with the unit file and the
   test script already on disk.

2. **Print the label** from `docs/PhoenixContact-BC-RPI-label.docx` (open it in Word first and
   check that the rows read J1.1 … J4.4 and H1 … LINK; the MAC in the side box is the new Pi's).

3. **Parts on the bench**, all from the two build docs: the 12 V wall wart for the I/O board
   (it measures 14.7 V) with bare wire ends for J4; the four 4-position PTSM plugs that shipped
   with the INT-PCB; three 3-position PTSM plugs for H1–H3; ferrules for any stranded conductor;
   22 AWG solid for pigtails; the new Pi's power supply (bring the old Pi's over, it is the same
   5 V USB-C feed off the `PivacPower` Shelly plug).

4. **Check the trunk gauge.** The 1-wire trunk is 18 AWG five-conductor. A PTSM 0,5 clamp takes
   20 AWG at most, so it will not enter H1's plug. Either do the CAT5e re-pull from
   `docs/ds18b20-bus-topology.md` §7.2 now, or make a pigtail: three lever connectors, trunk
   conductor in one side, 6 in of 22 AWG solid out the other, into the plug. The pigtail is
   the ten-minute route; the re-pull is the right one and can come later. The pigtail joint is
   where the bus went intermittent on cutover day, so the re-pull is the next job.

5. **Take the DS18B20 spare (`28-0516a36816ff`) off H1 on the bench board** so the field bus
   is the only thing on it, and move both boards, the link cable and the enclosure to the
   panel with the new Pi.

6. **Have the UniFi commands ready** on the Mac (step 3 runs them). The API key is at
   `~/.config/unifi/claude-agent.key`. The three client records, verified 2026-09-07:

   | Client | MAC | UniFi `_id` | Today |
   |---|---|---|---|
   | old Pi `eth0` | `d8:3a:dd:b1:ad:4d` | `6a31cc37d32f45306a8bfd73` | fixed `10.0.0.82` |
   | new Pi `eth0` | `2c:cf:67:80:55:00` | `6a9e09b277a1135d842469bd` | DHCP, last `10.0.0.40` |
   | old Pi `wlan0` | `d8:3a:dd:b1:ad:4e` | `66d627361149cc032426213b` | fixed `10.0.0.130` (moot: the Pi sets `.130` statically) |

## 1. Freeze the old Pi and take a fresh clone

The weekly clone is taken live and may predate config edits, so re-clone with the writers
stopped. That gives a consistent copy of InfluxDB, the Grafana database and the config as of
this minute. Run it in `tmux` so a dropped SSH session
cannot kill it.

```bash
ssh pi@10.0.0.82
tmux new -s cutover
sudo systemctl stop pivac-1wire pivac-redlink pivac-gpio pivac-arduino-psi pivac-arduino-therm-psi pivac-emporia pivac-sentry pivac-watermeter pivac-sprinkler pivac-domestic-water pivac-chiltrix pivac-loop-delta pivac-grafana-alerts signalk influxdb grafana-server nginx
lsblk -o NAME,SIZE,MOUNTPOINT | grep -A2 '^sd'        # the spare is the 119.2G sdX in the USB reader
sudo /home/pi/github/pivac/scripts/sd-clone.sh          # ~5 min incremental; ends "rpi-clone finished — exit 0"
```

Do not restart anything on the old Pi. It stays down from here; if step 8 fails, it goes back
in with its own card and everything resumes as before.

## 2. Prepare the spare card for the new hardware

Still on the old Pi, with the clone finished and unmounted. One check and three edits the new
Pi needs on its first boot, all made on the spare from here so nothing has to be typed blind at
the panel.

```bash
sudo mkdir -p /mnt/spare-boot /mnt/spare-root
sudo mount /dev/sdb1 /mnt/spare-boot        # substitute the sdX from step 1
sudo mount /dev/sdb2 /mnt/spare-root

# (0) the root partition the kernel will look for must be this card's, not the live card's
sudo blkid -s PTUUID -o value /dev/sdb; grep -o 'root=PARTUUID=[^ ]*' /mnt/spare-boot/cmdline.txt
#     expect the same eight hex digits in both lines. sd-clone.sh writes this; if they differ:
#     sudo sed -i -E "s/root=PARTUUID=[0-9a-f]{8}-02/root=PARTUUID=<blkid value>-02/" /mnt/spare-boot/cmdline.txt
#     A mismatch boots to a kernel that waits for root forever: ACT flashes, then stops, no network.

# (a) I²C on, w1-gpio overlay gone — delete the line, do not comment it (raspi-config re-enables a commented one)
sudo sed -i -e 's/^dtparam=i2c_arm=off$/dtparam=i2c_arm=on/' -e '/^dtoverlay=w1-gpio$/d' /mnt/spare-boot/config.txt
grep -n 'i2c_arm\|w1-gpio' /mnt/spare-boot/config.txt      # expect only: dtparam=i2c_arm=on

# (b) the DS2482 master on every boot
sudo cp /mnt/spare-root/home/pi/github/pivac/scripts/systemd/ds2482-init.service /mnt/spare-root/etc/systemd/system/
sudo systemctl --root=/mnt/spare-root enable ds2482-init
echo ds2482 | sudo tee /mnt/spare-root/etc/modules-load.d/ds2482.conf

# (c) nothing else: hostname, config.yml, keys, nginx, certs, Grafana and InfluxDB are the clone's own
sudo umount /mnt/spare-boot /mnt/spare-root
sudo poweroff
```

When the old Pi's lights stop, pull the spare card from the USB reader. Leave the old Pi's own
card in the old Pi. Label the old Pi "pivac, old, card intact, rollback" and set it aside.

## 3. Move the `10.0.0.82` reservation to the new MAC

From the Mac, before the new Pi is powered. The port forwards and every external URL point at
`.82`, and the reservation is by MAC.

```bash
KEY=$(cat ~/.config/unifi/claude-agent.key); B=https://10.0.0.1/proxy/network/api/s/default
# release: use_fixedip alone leaves fixed_ip set and the pin below is refused
curl -sk -X PUT -H "X-API-KEY: $KEY" -H 'Content-Type: application/json' \
  "$B/rest/user/6a31cc37d32f45306a8bfd73" -d '{"use_fixedip":false,"fixed_ip":""}'
# the old MAC is still an active station on .82 from its last lease; drop it or the pin is refused
curl -sk -X POST -H "X-API-KEY: $KEY" -H 'Content-Type: application/json' \
  "$B/cmd/stamgr" -d '{"cmd":"kick-sta","mac":"d8:3a:dd:b1:ad:4d"}'
curl -sk -X PUT -H "X-API-KEY: $KEY" -H 'Content-Type: application/json' \
  "$B/rest/user/6a9e09b277a1135d842469bd" \
  -d '{"name":"pivac","use_fixedip":true,"fixed_ip":"10.0.0.82","network_id":"63ab8c9d277b3e032baaa609"}'
```

All three return `"rc":"ok"` (`api.err.FixedIpAlreadyUsedByClient` on the pin means the release
or the kick did not take; `api.err.UnknownStation` on the kick is fine, the entry had already
aged out). Confirm:

```bash
curl -sk -H "X-API-KEY: $KEY" "$B/stat/user/2c:cf:67:80:55:00" | python3 -c 'import sys,json; d=json.load(sys.stdin)["data"][0]; print(d["use_fixedip"], d["fixed_ip"])'
```

Expect `True 10.0.0.82`.

## 4. Panel: power down and photograph

1. Breaker or plug off for the CDP relay panel's control power, and the `PivacPower` Shelly off
   (`curl "http://10.0.0.118/rpc/Switch.Set?id=0&on=false"`, or the app). Confirm the old Pi
   is dark.
2. Photograph the header wiring from two angles before touching a wire, close enough to read
   the label rows against the wires. Then tag each wire at the header with its label-row name
   (ZV, DHW, BLR, BOS2, BOS1, DEHUM, CHIL, ground, 1-wire, 3.3 V).
3. Remove the old Pi and its board from the enclosure.

## 5. Move the field wiring onto the plugs

The seven inputs keep their names and their BCM pins; only where the wire lands changes. On the
old board every relay contact returned to Pi ground. On the new board a channel is a contact
between a plug position and that plug's position 4, **24V COM**, which is the wall wart's
return and must never touch Pi ground. That one change is the point of the board.

| Wire tagged | Old landing | New landing | Plug pad on board |
|---|---|---|---|
| ZV | header pin 11 | **J1.1** | (6,2) |
| DHW | header pin 13 | **J1.2** | (7,2) |
| BLR | header pin 15 | **J1.3** | (8,2) |
| CHIL | header pin 22 | **J2.1** | (10,2) |
| BOS1 | header pin 31 | **J2.2** | (11,2) |
| BOS2 | header pin 29 | **J2.3** | (12,2) |
| DEHUM | header pin 32 | **J3.1** | (14,2) |
| SCALA | none (new 2026-09-07) | **J3.2** | (15,2) |
| relay common(s) | header ground pins | **position 4 of the plug that group uses** (J1.4, J2.4, J3.4); one common may serve all three, since every COM is one net | (9,2) (13,2) (17,2) |
| wall wart + | — | **J4.1** (+14 V in), landed **last** | (18,2) |
| wall wart − | — | **J4.4** (COM) | (21,2) |

Plug positions are counted left to right on the footprint in the board's TOP view, whatever
is printed on the plug body. Ferrules on stranded conductors; 22 AWG solid goes in bare.
Strain-relieve every cable at the enclosure entry.

Retired runs (Y2ON, Y2FAN, the old BOS1 on pin 18, YOFF on pin 37) were pulled in the relay
conversion; if any wire is still landed at the old header with no name in the table above,
coil and tag it, do not land it.

After landing, before power, three meter checks on the plugs (plugs inserted, board unpowered):

1. Each channel position to its plug's COM: open, or the relay's contact resistance if that
   relay happens to be closed. Never a dead short from a relay that should be open.
2. Any COM to the Pi's ground (a header ground pad, or the USB shell): **open**. A beep here
   means a common is still on Pi ground; find it before powering.
3. J4.1 to J4.4: open (the wart is not landed yet). Then land the wart, power it, and read
   +14 V between J4.1 and J4.4 with the correct polarity.

## 6. Fit the new Pi and the 1-wire trunk

1. Seat the new Pi in the enclosure on the I/O board, link cable to the EXT board, EXT board in
   its slot with H1–H3 at the short-end opening. Fit the label under the clear cover.
2. Old 1-wire hardware comes off and stays off: the 2.2 kΩ pull-up at the header, the GPIO 4
   data wire, and the 3.3 V and ground taps that fed the trunk. The DS2482 supplies power and
   pull-up itself; an external pull-up fights it.
3. Terminate the trunk (or its pigtail from step 0) in a 3-position PTSM plug, **VCC · DATA ·
   GND left to right** matching the socket's V/D/G pins (which reads GND · DATA · VCC from the
   front once the board is mounted solder side out), and plug it into **H1**. H2 and H3 stay
   empty; the outdoor run stays unplugged until it carries a probe.
4. Insert the spare card, connect Ethernet and the Pi's power lead, and turn the `PivacPower`
   Shelly back on.

## 7. First boot and GPIO verification

The clone boots as `pivac`, DHCP gives it `10.0.0.82`, and every pivac service starts on its
own. Give it two minutes, then from the Mac:

```bash
ssh pi@10.0.0.82 'hostname; cat /sys/class/net/eth0/address; uptime; ls /sys/firmware/devicetree/base | grep -c onewire; systemctl is-active ds2482-init signalk influxdb grafana-server nginx; systemctl list-units "pivac-*" --no-pager | grep -c running'
```

Expect `pivac`, `2c:cf:67:80:55:00`, `0` onewire nodes, everything `active`, and 12 running
pivac units (13 listed, `pivac-watermeter` disabled). If SSH answers at `.40` instead of `.82`,
the reservation in step 3 did not take; fix it and `sudo systemctl restart NetworkManager`.

**Prove each channel end to end.** The bench script reads the pins directly, so stop
`pivac-gpio` first, then run its live table while relays are exercised at the panel:

```bash
ssh pi@10.0.0.82
sudo systemctl stop pivac-gpio
sudo python3 ~/github/pivac/scripts/io-board-test.py --monitor
```

Every channel idles high (inactive). Then make each relay close and watch exactly one row drop:

| Channel | How to make the relay close | What else may move |
|---|---|---|
| BOS1 | call the KITCHEN zone at its thermostat | nothing else |
| BOS2 | call the GREAT_ROOM zone | nothing else |
| CHIL | call MASTER_BR, DSTRS_FAM_ROOM or KIDS_ROOM | CHIL may already be on, the Chiltrix runs to tank setpoint |
| DHW | draw hot water until the DHW call lands | BLR may follow, that is the boiler answering |
| BLR, ZV | a heat call on any hydronic zone (raise a setpoint) | ZV and BLR move together on a heat call |
| DEHUM | the dehumidifier's call, or a jumper from J3.1 to J3.4 | nothing else |

BOS1 and BOS2 are the pair to be sure of: crossed relays look healthy in every other test. A row
that drops together with another when only one relay closed is the bridge the bench test rules
out, so it would be field wiring, a common on the wrong plug. Ctrl-C, then:

```bash
sudo systemctl start pivac-gpio; sleep 15
curl -s http://127.0.0.1:3000/signalk/v1/api/vessels/self/electrical/ac/switch/utility \
  | python3 -c 'import sys,json; print({k:v["statenum"]["value"] for k,v in json.load(sys.stdin).items()})'
```

Exactly seven inputs: ZV, DHW, BLR, BOS2, BOS1, DEHUM, CHIL. (`status()` cannot be called bare;
it needs the module's config block, so read the daemon's output instead.)

## 8. 1-wire verification

```bash
ssh pi@10.0.0.82 'readlink /sys/bus/i2c/devices/1-0018/driver; cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slave_count; ls /sys/bus/w1/devices/ | grep ^28-'
```

Expect the driver link ending `ds2482`, a count of **8**, and the eight ROMs in the CLAUDE.md
roster (`c98b14`, `1aa0a8`, `c9e879`, `c915c1`, `cc0c90`, `1a9154`, `1ac0a9`, `c99b56`). Then
the proof from `docs/ds18b20-bus-topology.md` §7.3, forty sweeps, about three minutes:

```bash
ok=0; bad=0; miss=0
for i in $(seq 1 40); do
  [ "$(cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slave_count)" -ne 8 ] && miss=$((miss+1))
  for d in /sys/bus/w1/devices/28-*; do
    case "$(head -1 $d/w1_slave)" in *YES*) ok=$((ok+1));; *) bad=$((bad+1));; esac
  done
  sleep 4
done
echo "crc_ok=$ok crc_fail=$bad sweeps_not_8=$miss"
grep . /sys/bus/w1/devices/28-*/ext_power
```

Pass is `crc_fail=0 sweeps_not_8=0` and `ext_power` of 1 on all eight. A count short of eight
with clean CRCs is a probe not reaching a block; a count of eight with CRC failures is a bus
with no margin, and the first suspect is the pigtail. `pivac-1wire` needs no restart, it
rescans every cycle.

## 10. Rollback

At any point up to step 9: power the new Pi down, put the old Pi and its own card back on the
old header wiring (the photographs from step 4), and move the reservation back:

```bash
KEY=$(cat ~/.config/unifi/claude-agent.key); B=https://10.0.0.1/proxy/network/api/s/default
curl -sk -X PUT -H "X-API-KEY: $KEY" -H 'Content-Type: application/json' "$B/rest/user/6a9e09b277a1135d842469bd" -d '{"use_fixedip":false,"fixed_ip":""}'
curl -sk -X POST -H "X-API-KEY: $KEY" -H 'Content-Type: application/json' "$B/cmd/stamgr" -d '{"cmd":"kick-sta","mac":"2c:cf:67:80:55:00"}'
curl -sk -X PUT -H "X-API-KEY: $KEY" -H 'Content-Type: application/json' "$B/rest/user/6a31cc37d32f45306a8bfd73" -d '{"use_fixedip":true,"fixed_ip":"10.0.0.82","network_id":"63ab8c9d277b3e032baaa609"}'
```

The wlan0 reservation (`10.0.0.130`) moves the same way between `66d627361149cc032426213b`
(old, `d8:3a:dd:b1:ad:4e`) and `6a9e0b1677a1135d84246a04` (new, `2c:cf:67:80:55:01`).

The old Pi's card is untouched by this procedure, so it boots as it did this morning; only the
data written to the new Pi in between is lost.
